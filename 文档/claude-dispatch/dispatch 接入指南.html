dispatch 接入指南

在另一台电脑上装好 dispatch，或者交给另一个人使用：安装插件，接上知识库和文档站，再在项目里启用。插件本身不含任何个人路径，个人的东西都放在各自电脑的配置文件里。

约 10 分钟 需要 git、python3 知识库、文档站可选
装哪些东西

三样东西，分放三处

只有插件是必装的。知识库和文档站不配置，相关规则就不会注入会话，也不占上下文。

内容放在哪怎么来
插件GitHub 仓库 Lhanman/claude-dispatch用插件市场安装，每台电脑一次
个人配置~/.claude/dispatch/config知识库和文档站的路径、敏感词；每台电脑各写一份
项目配置各项目的 CLAUDE.md在项目里执行 /dispatch:setup 生成：验证命令、知识库对应目录

开发机（插件源码所在的电脑）用的是软链方式：~/.claude/skills/dispatch 指向源码目录，改完执行 /reload-plugins 就生效。其他电脑都用插件市场安装。同一台电脑上两种方式只能选一种，否则插件会加载两次。

准备

先确认这几样

依赖用途检查方法
Claude Code支持插件的版本claude plugin --help 能列出 install、marketplace
git + SSH从 GitHub 安装插件；发布文档站ssh -T git@github.com 回复 Hi 用户名
python3hook 解析、知识库检索、文档站发布python3 --version；没有时知识库和文档站功能不启用
OpenSpec（可选）L3 以上的规格流程openspec --version；安装：npm i -g @fission-ai/openspec

插件仓库如果是私有的，别人要先被加为仓库协作者，才能装得上。

安装插件

两条命令

claude plugin marketplace add git@github.com:Lhanman/claude-dispatch.git
claude plugin install dispatch@claude-dispatch

# 确认：状态为 loaded，版本与仓库一致
claude plugin list
claude plugin details dispatch   # 顺便看每个会话的常驻 token 开销

装完后新开一个会话，路由规则在会话开始时才注入。

个人配置

接上知识库和文档站

最省事的方式是在任意项目里执行 /dispatch:setup，它会问你知识库在哪，再替你写配置。下面是手动配置的方法。

A · 你自己的另一台电脑把两个仓库克隆下来，复制配置
  1. 克隆知识库：git clone git@github.com:Lhanman/lhan_doc.git ~/workbench/lhan_doc
  2. 克隆文档站：git clone git@github.com:Lhanman/lhanman.github.io.git ~/workbench/lhanman.github.io
  3. 从开发机复制 ~/.claude/dispatch/config，路径不同就改掉
B · 已有自己知识库的其他人把插件指向他自己的目录，不搬数据
  1. kb_dir 指向他自己的 Markdown 笔记目录，例如 Obsidian 库
  2. 不需要改原有笔记：没有 frontmatter 的笔记，用一级标题和第一段当摘要
  3. 文档站可选：自建一个 <用户名>.github.io 仓库，再填 pages_* 这几项

配置文件示例

# ~/.claude/dispatch/config（每台电脑一份，不进插件仓库）

# 知识库：按目录组织的 Markdown 笔记
kb_dir=~/workbench/lhan_doc
kb_exclude=copilot                      # 不参与检索的顶层目录，逗号分隔

# 文档站：生成的 HTML 自动发布到这里（公开）
pages_repo=~/workbench/lhanman.github.io
pages_url=https://lhanman.github.io
pages_title=Lhanman 的文档
pages_deny=公司名,内部项目名             # 发布前拦截的敏感词
  • 文档站仓库第一次发布时，会自动生成 .github/ 下的部署流程。要到仓库的 Settings → Pages → Source 选 GitHub Actions，线上网址是英文的 /p/<slug>/。
  • GitHub Pages 的站点是公开的，即使仓库是私有的也一样。pages_deny 填上自己的公司名和内部项目名，命中就不发布。
  • 知识库只有你自己能看到，不需要这层把关；dispatch 往知识库里写笔记之前，都会先给你看。
在项目里启用

每个项目执行一次 /dispatch:setup

  1. 探测构建方式读取 package.json、Gradle、Makefile、CI 配置等，只读，不执行构建。
  2. 拟定验证矩阵L0 到 L3 以上每一级各一条能直接执行的命令，给你确认。
  3. 检查 git 和 OpenSpec不是 git 仓库时提醒你，但不会替你初始化；没有 OpenSpec 时，L3 的方案会写到 docs/plans/。
  4. 确定知识库目录这个项目的笔记放在知识库的哪个目录：已有对应目录就复用，没有就用项目名。

确认后写进项目的 CLAUDE.md，只新增或替换下面两节，不动文件里的其他内容：

## dispatch 验证矩阵

验证命令一律通过 `dispatch-verify <命令>` 执行。

| 级别 | 命令 |
|---|---|
| L0 | …… |
| L1 | …… |
| L2 | …… |
| L3 以上 | …… |

## dispatch 知识库

目录：<项目目录>/

不执行 setup 也能用：没有验证矩阵时，会根据构建文件推断验证命令。

检查是否接好

在新会话里逐项试一下

dispatch-* 这几个命令只在 Claude Code 的会话里可用，插件启用期间会自动加进会话的 PATH；在普通终端里找不到它们，直接让 Claude 执行就行。

试什么怎么试正常结果
路由规则提一个开发需求回复第一行是 〔L2 · 依据〕 这样的判定
手动级别消息里写 #L1判定行是 〔L1 · 用户指定〕；overrides.log 多一行
验证脚本dispatch-verify echo ok✔ 通过 · 退出码 0
知识库dispatch-kb path，再 dispatch-kb search <词>打印知识库目录；每篇笔记一行
文档站dispatch-pages url，再 dispatch-pages list打印站点网址；每篇文档一行
脑暴说「脑暴一下……」发散出 8–12 个想法，再归类对比、推荐方向
更新与卸载

开发机推送，其他电脑拉取

# 开发机：改完源码后
git -C ~/workbench/claude-dispatch commit -am "说明这次改了什么"
git -C ~/workbench/claude-dispatch push

# 其他电脑：拉取并更新，然后在会话里执行 /reload-plugins
claude plugin marketplace update claude-dispatch
claude plugin update dispatch@claude-dispatch

# 卸载（~/.claude/dispatch/ 里的配置和日志会保留）
claude plugin uninstall dispatch@claude-dispatch

版本号写在插件仓库的 .claude-plugin/plugin.json 里。改了功能就升一下版本号，其他电脑用 claude plugin list 就能看出装的是不是最新版。

常见问题

装不上或不生效时

装不上：Repository not found？
SSH 没通，或者没有这个私有仓库的权限。先执行 ssh -T git@github.com，再确认自己已被加为仓库协作者。
装好了，但回复里没有判定行？
规则只在新会话、/clear、/compact 之后注入，已经开着的会话不会生效。另外，问答、调研、脑暴类请求本来就不写判定行。
同一个插件加载了两次？
同一台电脑上既有 ~/.claude/skills/dispatch 软链，又从插件市场装了一份。两种方式只保留一种。
知识库或文档站的规则没出现？
执行 dispatch-kb path 或 dispatch-pages url，看报错。常见原因：配置文件里的路径不存在、目录不是 git 仓库，或者这台电脑没有 python3。
文档站发布失败？
退出码 3：敏感检查没通过，按提示修改内容或放行。退出码 4：已提交到本地但推送失败，检查 SSH。推送成功但网站没更新：确认仓库的 Pages 发布来源选的是 GitHub Actions。
和别的流程插件冲突？
不要同时启用另一套「每个任务都强制走流程」的插件，例如 superpowers。两套路由规则会互相冲突，还会重复占用上下文。
