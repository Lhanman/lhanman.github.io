Skill · 访谈

grill-me：拷问式需求梳理

写代码之前，让 AI 追着问，直到每个设计决策都有答案。它不写任何文件，只是把你的想法梳理清楚。

怎么启动

/dispatch:grill-me 我想给播放器加倍速和画中画功能
  • 只能你手动输入 /dispatch:grill-me 触发，AI 不会自己调用。
  • 最好在新会话里用，并且不要开 Plan 模式。Plan 模式会让 AI 急着出计划，而这里的目的是先把问题问透。

它怎么提问

AI 把你的想法拆成一棵决策树。凡是前提已经确定、现在就能问的问题，它每轮一次问完，每题都附上推荐答案。能从代码或环境里查到的事实，它会自己查，不来问你。

示例 · 第 1 轮
❓ Q1 · 倍速范围：0.5x–2x，还是 0.25x–4x？
➡️ 推荐 0.5x–2x。能覆盖绝大多数场景，Android 的 ExoPlayer 和 iOS 的 AVPlayer 都能稳定支持。
❓ Q2 · 画中画触发方式：用户点按钮进入，还是切到后台时自动进入？
➡️ 推荐两种都支持，自动进入做成设置里的开关。
❓ Q3 · 倍速是否记忆：按视频分别记，还是全局记一个？
➡️ 推荐全局记一个，实现简单，也更符合大多数用户的预期。

你回答后，它会重新整理决策树，问下一轮。所有分支都问完才算结束。结束前它不会动手，要等你确认双方理解一致。

用好它的要点

主动掌控范围敢反驳、敢说"不知道"、发现跑题就指出来。一路"同意、同意"下来的会话，结论其实是 AI 替你定的。
靠聊聊不清的问题，先做原型像"交互手感怎么样"这类问题，要先有个东西看。遇到时就停下来做个原型，看完再回来一句话回答。
问题太多说明范围太大看的是问了几轮，不是几个问题：4 轮 40 多个问题很正常。如果远超这个量，先让它把需求拆小，再逐块拷问。
想一次只问一个问题在 ~/.claude/CLAUDE.md 里加一行：When grilling, ask one question at a time.
CLI + 斜杠命令 · 规格

OpenSpec：规格驱动开发

在项目里加一层轻量的规格：先在 Markdown 里和 AI 对齐要做什么，再写代码。每个需求变更都有自己的文件夹，里面有提案、规格、设计和任务清单。

初始化（每个项目一次）

cd ~/workbench/kmp-video-player
openspec init --tools claude    # 生成 openspec/ 目录和 /opsx:* 命令
openspec config set telemetry.enabled false   # 可选：关闭匿名统计

核心命令（在 Claude Code 对话里输入）

命令作用
/opsx:explore自由探讨：读代码、比较方案，不写代码。适合想法还模糊的时候
/opsx:propose创建一个变更，一次生成 proposal、specs、design、tasks
/opsx:apply按 tasks.md 逐项实现
/opsx:update修改变更里的规划文档，保持前后一致
/opsx:sync把变更里的规格增量合并进主规格
/opsx:archive变更完成后归档，同时更新主规格

一个变更的完整流程

  1. /opsx:explore 播放器要支持字幕，但不确定用哪种格式把方向讨论清楚。这一步不写任何文件。
  2. /opsx:propose add-subtitle-support生成 openspec/changes/add-subtitle-support/ 下的 proposal.md、specs/、design.md、tasks.md
  3. 审阅，必要时 /opsx:update在写代码之前改规格，比写完再改便宜得多。
  4. /clear → /opsx:apply建议先清空上下文，再按任务清单实现。
  5. /opsx:archive归档到 openspec/changes/archive/，主规格同步更新。

规格长什么样

就是普通 Markdown，用 SHALL / WHEN / THEN 描述需求和验收场景：

## ADDED Requirements
### Requirement: 倍速播放
播放器 SHALL 支持 0.5x–2x 倍速，默认 1x。

#### Scenario: 用户切换倍速
- **WHEN** 用户选择 1.5x
- **THEN** 播放速度变为 1.5x，且音调不变

扩展命令（可选）

运行 openspec config profile 勾选需要的工作流，再在项目里运行 openspec update，就能用上这些：

/opsx:new + /opsx:continue逐个生成规划文档
/opsx:ff一次生成全部规划文档
/opsx:verify检查实现是否符合规格
/opsx:bulk-archive一次归档多个变更
/opsx:onboard带你走一遍完整流程的教程

常用终端命令

openspec list        # 查看进行中的变更
openspec update      # 升级 CLI 后，刷新项目里的 AI 指令
openspec --help      # 查看全部命令
搭配

两者怎么串起来

grill-me：把想法问清楚

适合想法还模糊的时候。不生成文件，不依赖代码仓库，产出是一组已经确定的决策。

OpenSpec：把需求落成文档

适合需求已经确定的时候。把它写成规格和任务清单，再按清单实现、验收、归档。

  1. /dispatch:grill-me 字幕功能在新会话里开始，关掉 Plan 模式。
  2. /opsx:propose add-subtitle-support在同一个会话里接着用，前面问出来的内容会直接写进规格。
  3. /clear → /opsx:apply → /opsx:archive清空上下文后实现、归档。
