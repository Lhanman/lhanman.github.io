特助手 功能清单与矩阵

围绕特斯拉用车场景，做周边设备互联和车机控制。把车变成一台能被手机、手表、语音和家里设备顺手调用的设备。

20 项功能 候选清单，不排期 优先级待定 20 项均已调研 个人自用 demo 阶段

体验价值

每个功能都问一句：能不能少一步、少一次等待，或者多一点仪式感。下文用这四个标签。

省一步

原本要在车机或官方 App 里点几下，现在一句话或一个按钮搞定。

免等待

上车前就把温度、座椅、导航备好，不用坐进去再等。

仪式感

一个场景名对应一组动作，比如“下班模式”“午休模式”。

安心

离车后门窗、充电状态心里有数，该提醒的会提醒。

整体结构

入口很多，出口只有一个：所有车控都经过指令网关，分级和确认只做一次。

虚线是近场蓝牙，不经过云端，对应 P4。导航分析（N1–N3）只读，不走指令网关，直接使用数据通道里的数据。

功能清单

五组共 20 项。标签表示车辆影响：只读、可逆、需确认。

模块一

导航预测准确度分析

已有调研
  • N1
    导航数据采集 只读
    记录起点、终点、车机预计到达时间、实际到达时间、轨迹
  • N2
    路线级准确度统计 只读
    把常走路线归类，算长期预测偏差
  • N3
    偏差规律分析 只读
    按早高峰、平峰、晚高峰和路段拆解，看系统性偏早还是偏晚
模块二

车机控制

8 项
  • C1
    预热 / 预冷场景 可逆
    一键启动空调，同时开座椅和方向盘加热，可设定时
  • C2
    离车检查与一键锁 可逆
    查门窗、后备箱、充电口是否关好，再锁车
  • C3
    露营 / 午休场景 可逆
    空调保持运行，同时设电量下限，低于下限提醒
  • C4
    目的地下发 可逆
    从手机分享菜单把地点推到车机导航
  • C5
    充电管理 可逆
    调充电上限和电流，启停充电，设定时充电
  • C6
    找车 可逆
    闪灯、鸣笛
  • C7
    开锁与开启类操作 需确认
    解锁、前后备箱、通风窗，每次先确认
  • C8
    媒体控制 可逆
    播放、暂停、切歌、音量
模块二

周边互联

5 项
  • P1
    语音入口
    Siri 和快捷指令，一句话触发场景
  • P2
    手表与小组件
    Apple Watch、桌面小组件，常用场景一键点
  • P3
    智能家居联动
    家里的按键或场景触发车辆动作，比如玄关按键启动预热
  • P4
    近场蓝牙控制
    走 Tesla BLE，不经云端，停车库没信号也能用
  • P5
    车辆事件推送 只读
    充电完成、车门未关、哨兵触发推到手机或手表

风险分级与网关规则

和项目约定一致：涉及开锁、开门类指令先让用户确认。

包含 N1–N3、P5、S1

可逆 直接执行，留日志

包含 C1–C6、C8

调研结论

20 项功能各由一个子代理查官方资料，2026-10-16 完成。20 项都只到“部分可行”：官方资料能支撑大方向，但没有一项到“已确认可行”，也没有一项被判为不可行。多数卡在中国区、官方页没写参数、需要真车实测。标“已复核”的结论，我又直接打开官方页面核对过。

1

中国大陆是最大的阻塞项

已复核
  • 中国区有独立端点 fleet-api.prd.cn.vn.cloud.tesla.cn，调用中国车辆要在 developer.tesla.cn 另建应用，需要 +86 手机号。
  • 官方“可付费和修改计费限额”的国家名单里没有中国大陆，计费限额默认为 0。中国大陆账号能否开通计费、各功能在国内车型上能否使用，官方没有说明。
  • Home Assistant 官方 Tesla Fleet 集成明确写了不支持中国区（调研引用，未复核）。developer.tesla.cn 的文档页抓取为空。
2

REST 导航字段官方页没有列

已复核
  • 官方 vehicle_data 页没有响应示例和字段说明，active_route_* 只见于第三方资料。
  • 官方 Telemetry proto 里有 MinutesToArrival、DestinationName、RouteLine 等对应字段，固件 2024.26 及以上。N1 更稳的做法是走 Telemetry。
3

轮询的成本远超免费折扣

已复核
  • 官方单价：Data 500 次/$1，Commands 1,000 次/$1，Wakes 50 次/$1，Streaming 150,000 信号/$1，每账号每月 $10 折扣。
  • 每分钟轮询一次约 43,200 次/月，约 $86。$10 折扣只够约 5,000 次 Data 请求，平均每天约 160 次。
  • 限流：Realtime Data 60 次/分钟，Wakes 3 次/分钟，Device Commands 30 次/分钟。计费限额默认为 0，超限后 API 暂停，Telemetry 配置被删除且不会恢复。
4

签名只有通用规则

已复核
  • 官方指令页只点名 set_pin_to_drive、reset_pin_to_drive_pin、set_vehicle_name 三个指令必须使用 Vehicle Command Protocol。
  • 通用规则：未签名的指令会被车辆拒绝，不执行任何动作。其余指令是否逐条要求签名官方没列，保守做法是全部经签名代理发送。
5

指令参数名官方页大多没写

已复核
  • 指令页只写了 actuate_trunk 的 which_trunk（front / rear）和 window_control 关窗时的 lat、lon。
  • set_climate_keeper_mode 取值为 0–3，没有写参数名。其余指令的参数名和类型要对照 OpenAPI 描述、官方 SDK 源码或实测。

逐项调研结果

每一项的完整记录和来源在仓库的 docs/research 目录。

ID功能等级已确认未证实或风险
N1导航数据采集部分可行Telemetry 路线字段存在，固件 2024.26+REST active_route_* 官方页未列；开始和到达无官方事件；中国区 Telemetry
N2路线级准确度统计部分可行起终点坐标、RouteLine、预计到达分钟可作归类数据源归类算法需自研；TeslaMate 的做法未读到源码
N3偏差规律分析部分可行官方只有整条路线的剩余分钟数，没有路段级 ETA 和拥堵字段；时间戳字段官方标注可能错误沿途偏差曲线靠高频采样推演，不是官方能力
C1预热 / 预冷场景部分可行auto_conditioning_start/stop、set_temps、座椅和方向盘加热（需预热或保温已开）、add_precondition_schedule参数名类型；休眠时是否需先唤醒；逐条签名要求
C2离车检查与一键锁部分可行door_lock、window_control（关窗需 lat/lon，仅停放车辆）、actuate_trunk、充电口开关；Telemetry 门、窗、锁、充电口字段vehicle_data 车身字段名；Telemetry 触发机制；中国区
C3露营 / 午休场景部分可行set_climate_keeper_mode 取值 0–3；Telemetry BatteryLevel保持时长和自动退出官方无说明（社区称电量 20% 退出）；官方无电量阈值订阅，提醒要在应用侧比较
C4目的地下发部分可行navigation_request、navigation_gps_request（可指定多停靠点顺序）等指令存在请求体字段；车机用 GCJ-02 还是 WGS-84；从分享菜单取到什么数据
C5充电管理部分可行启停充电、充电上限、充电电流、充电口开关；定时充电旧指令 2024.26 起不推荐，改用 add_charge_schedule；scope vehicle_charging_cmds参数名和单位；charge_state 字段名；第三方家用桩影响
C6找车部分可行flash_lights、honk_horn，官方明写需要 P 档逐条签名要求；休眠唤醒延迟
C7开锁与开启类操作部分可行door_unlock、actuate_trunk、window_control（vent / close）、sun_roof_control；需虚拟钥匙，未签名被拒是否要求 PIN 或车主在场官方未写；程序化撤销 token 的方式
C8媒体控制部分可行播放暂停、上下曲、上下收藏、音量加减、adjust_volume（需用户在车内且开启移动访问）；Telemetry 有播放状态和曲目字段无法指定 QQ 音乐或网易云；中国区表现
P1语音入口部分可行「获取 URL 内容」支持 POST 和 JSON 请求体；Siri 短语可运行快捷指令自定义 Authorization Header 只有社区经验；锁屏免解锁；令牌存放；大陆实测
P2手表与小组件部分可行快捷指令小组件点按直接运行；Apple Watch 复杂功能可运行；免费账号侧载 7 天过期手表是否依赖 iPhone 在附近；点按后是否多一次确认
P3智能家居联动部分可行Home Assistant 的 rest_command 支持自定义 Header 和 POSTHA Tesla 集成不支持中国区；Apple Home 自动化内请求行为有争议；米家无官方依据
P4近场蓝牙控制部分可行tesla-control 支持 BLE，示例为 lock；密钥登记需车内 NFC 卡；官方平台为 macOS 和 Linux其他指令、只读状态、距离延迟；iOS 只有社区包；大陆可用性
P5车辆事件推送部分可行Telemetry 按变化推送，可设最小间隔；充电、门、窗、哨兵、锁车字段存在；官方没有免自建的接收方式充电完成的枚举；哨兵触发对应状态；Bark 在大陆的送达；中国区
S1车辆状态面板部分可行vehicle_data 是实时调用，官方不推荐定期轮询（已复核：官方页未列分组、字段、休眠行为）电量、胎压、温度所在字段；休眠车辆返回什么
F1授权与密钥部分可行申请应用、托管公钥、partner 注册、OAuth 授权码、虚拟密钥流程；refresh token 一次性、3 个月有效个人自用是否审核；access token 有效期；中国区账号实际能否跑通
F2指令网关部分可行未签名指令被拒；tesla-http-proxy 把 REST 调用转成签名协议；官方库仅 Go哪些车型和固件必须签名官方无清单；中国区车辆能否配对
F3数据通道部分可行官方单价、折扣、限流、限额规则（已复核）；官方推荐 Telemetryvehicle_data 是否唤醒休眠车辆、是否计入 60 次/分钟；中国区计费

调研代理读不到的页面：developer.tesla.com 的 vehicle-data 子页和 base-urls 页返回 404，developer.tesla.cn 文档页内容为空。涉及这两处的结论都标了“无法证实”。

待确认

  1. 中国区能否走通：用 tesla.cn 账号和 developer.tesla.cn 应用实际注册，确认能否授权、能否设计费限额、车控和 Telemetry 是否可用。这一步不通，其他功能都无从谈起。
  2. 自己的车型是否需要 Vehicle Command Protocol 签名，公钥怎么部署到车上。
  3. vehicle_data 对休眠车的行为和计费类别，用一次性调用实测。
  4. 常驻服务放在哪：本机、家里的小主机，还是云端。这决定指令网关和 Telemetry 接收端的形态，数据是否出境也要一并考虑。
  5. P3 用哪个家居平台，目前未选。
  6. P4 的 BLE 在自己的车上支持哪些指令。

验证顺序：先注册开发者账号、完成授权、实测 vehicle_data，再试一条可逆的车控指令。
