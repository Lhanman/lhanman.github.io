特助手 功能清单与矩阵

围绕特斯拉用车场景，做周边设备互联和车机控制。把车变成一台能被手机、手表、语音和家里设备顺手调用的设备。

20 项功能 候选清单，不排期 优先级待定 个人自用 demo 阶段

体验价值

每个功能都问一句：能不能少一步、少一次等待，或者多一点仪式感。下文用这四个标签。

省一步

原本要在车机或官方 App 里点几下，现在一句话或一个按钮搞定。

免等待

上车前就把温度、座椅、导航备好，不用坐进去再等。

仪式感

一个场景名对应一组动作，比如“下班模式”“午休模式”。

安心

离车后门窗、充电状态心里有数，该提醒的会提醒。

整体结构

入口很多，出口只有一个：所有车控都经过指令网关，分级和确认只做一次。

虚线是近场蓝牙，不经过云端，对应 P4。导航分析（N1–N3）只读，不走指令网关，直接使用数据通道里的数据。

功能清单

五组共 20 项。标签表示车辆影响：只读、可逆、需确认。

模块一

导航预测准确度分析

已有调研
  • N1
    导航数据采集 只读
    记录起点、终点、车机预计到达时间、实际到达时间、轨迹
  • N2
    路线级准确度统计 只读
    把常走路线归类，算长期预测偏差
  • N3
    偏差规律分析 只读
    按早高峰、平峰、晚高峰和路段拆解，看系统性偏早还是偏晚
模块二

车机控制

8 项
  • C1
    预热 / 预冷场景 可逆
    一键启动空调，同时开座椅和方向盘加热，可设定时
  • C2
    离车检查与一键锁 可逆
    查门窗、后备箱、充电口是否关好，再锁车
  • C3
    露营 / 午休场景 可逆
    空调保持运行，同时设电量下限，低于下限提醒
  • C4
    目的地下发 可逆
    从手机分享菜单把地点推到车机导航
  • C5
    充电管理 可逆
    调充电上限和电流，启停充电，设定时充电
  • C6
    找车 可逆
    闪灯、鸣笛
  • C7
    开锁与开启类操作 需确认
    解锁、前后备箱、通风窗，每次先确认
  • C8
    媒体控制 可逆
    播放、暂停、切歌、音量
模块二

周边互联

5 项
  • P1
    语音入口
    Siri 和快捷指令，一句话触发场景
  • P2
    手表与小组件
    Apple Watch、桌面小组件，常用场景一键点
  • P3
    智能家居联动
    家里的按键或场景触发车辆动作，比如玄关按键启动预热
  • P4
    近场蓝牙控制
    走 Tesla BLE，不经云端，停车库没信号也能用
  • P5
    车辆事件推送 只读
    充电完成、车门未关、哨兵触发推到手机或手表
状态

车辆状态面板

1 项
  • S1
    车辆状态面板 只读
    电量、续航、门窗、胎压、车内温度，只读
基础

基础设施

3 项
  • F1
    授权与密钥
    Fleet API 的 OAuth 授权，车端公钥部署，密钥不入库
  • F2
    指令网关
    统一收口车控：签名、风险分级、确认、操作日志
  • F3
    数据通道
    轮询 vehicle_data 或接 Fleet Telemetry，决定采集频率

风险分级与网关规则

和项目约定一致：涉及开锁、开门类指令先让用户确认。

只读 直接执行

包含 N1–N3、P5、S1

网关 控制查询频率，避免频繁唤醒车辆

可逆 直接执行，留日志

包含 C1–C6、C8

网关 写操作日志，随时可撤回

需确认 确认后执行

包含 C7 解锁、前后备箱、通风窗

网关 弹确认后执行并留日志；开发调试期默认不发

待确认

  1. 自己的车型是否需要 Vehicle Command Protocol 签名，公钥怎么部署到车上。
  2. 车控指令的调用频率限制和计费。
  3. 常驻服务放在哪：本机、家里的小主机，还是云端。这决定指令网关和 Telemetry 接收端的形态。
  4. P3 用哪个家居平台，目前未选。
  5. P4 的 BLE 方案在官方 SDK 里的支持程度。

验证顺序：先注册开发者账号、完成授权、实测 vehicle_data，再试一条可逆的车控指令。
