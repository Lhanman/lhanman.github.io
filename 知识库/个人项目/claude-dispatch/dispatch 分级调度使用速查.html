结论

  • 平时直接说需求。开发类请求会自动定级 L0–L4，回复第一行写 〔L2 · 依据〕；L3 以上先征得你同意。问答、调研类请求不定级。
  • 想指定级别，就在消息里写 #L0–#L4。指定的级别是下限：要升级时会先停下问你，回复 #L3 这样的标记确认。每次指定和确认都会记入 ~/.claude/dispatch/overrides.log，用来修订定级规则。
  • 要脑暴时说「脑暴一下……」或执行 /dispatch:brainstorm。
  • 新项目先执行一次 /dispatch:setup：把验证命令和知识库目录写进项目 CLAUDE.md。
  • 验证一律用 dispatch-verify <命令>；查知识库用 dispatch-kb search；沉淀笔记用 /dispatch:note，写之前会先给你确认。
  • 生成的 HTML 文档会自动发布到公开文档站 https://lhanman.github.io/ ，只有敏感检查命中时才停下来问你。
  • 插件源码在 ~/workbench/claude-dispatch（0.5.0），改完在会话里执行 /reload-plugins。

步骤

级别与流程

级别什么样的任务流程
L0 直做一句话说得清直接改 → 最小验证
L1 快修位置明确，≤3 个文件，不碰公共接口三行意图 → 复现测试 → 改 → 验证
L2 标准跨模块、需求有歧义、新依赖，或碰公共接口、数据模型、并发、删除查知识库 → scout（按需）→ grilling ≤1 轮 → Plan 模式 → 测试先行 → 验证 → reviewer 审一次
L3 特性一个会话做不完；改接口或持久化格式；新增完整能力grill-me → /opsx:propose → 你审规格 → /opsx:apply（每组审一次，组间 /clear）→ Opus 终审 → /opsx:verify → /opsx:archive → note
L4 史诗新子系统或大改造/opsx:explore 定决策 → 拆成多个 L3，最多 3 路并行（需 git worktree）

执行中任务变大或变小会升降级：改动文件超预估 2 倍、同一问题修 2 轮没好、碰到公共接口或迁移时升级；问不出未决问题、只需改 1 个文件时降级。

命令

命令作用
/dispatch:setup项目接入：验证矩阵、git、OpenSpec、知识库目录
/dispatch:grill-meL3 需求拷问，问到没有未决问题为止
/dispatch:brainstorm脑暴：发散 8–12 个想法 → 归成 3–4 个方向对比 → 推荐 1–2 个
/opsx:propose · apply · verify · archiveOpenSpec：提案 → 按任务组执行 → 核对规格 → 归档
/opsx:exploreL4 先探索、定架构决策
/dispatch:note把方案、决策、踩坑或指南写进知识库（先确认）
dispatch-verify <命令>跑验证，只回显摘要，完整日志存临时文件
dispatch-kb search｜outline｜dirs｜list分层检索知识库，每篇笔记一行
dispatch-pages publish｜search｜list｜remove发布 HTML 到文档站、查找已发布的文档、下线
#L0–#L4手动指定本次级别（下限，升级要你确认）

角色模型什么时候用

检索知识库（省上下文）

  1. dispatch-kb search <词> -d <项目目录>：每篇笔记一行（路径 │ 类型 │ 日期 │ 摘要）。同一概念的几种说法用 | 连成一个词，如 报错|故障|异常；同一篇的多个版本只显示最新的，加 --all 看全部。
  2. dispatch-kb outline <路径>：摘要加带行号的标题大纲。
  3. 用 Read 的 offset/limit 只读需要的那一节。

文档站

  1. 发布 Artifact 页面后，hook 会给出现成的命令：dispatch-pages publish <文件> --slug <英文短名> --desc "<一句话>" --tags <标签> --project <项目>。同一个 slug 再发布就是更新。
  2. 发布前先做敏感检查：本机路径、邮箱、密钥、pages_deny 里的敏感词、Artifact 专属能力。命中就不发，退出码 3；确认无妨后用 --allow 词 放行。
  3. 文件放在 文档/<项目>/<标题>.html，没有项目的放 文档/其他/；本地在 ~/workbench/lhanman.github.io 里按标题就能找到。线上网址是英文的 https://lhanman.github.io/p/<slug>/，推送后由 GitHub Actions 部署，约 1 分钟生效。站点是公开的，工作内容不发。

常见问题

  • 没出现判定行？ 规则在新会话、/clear 或 /compact 后才注入。
  • 定级不准？ 用 #L 纠正；用上 1–2 周后看 overrides.log，据此修改 router/ROUTER.md。
  • 额度不够用？ 约 90% 消耗在主会话，先降主会话模型或 /effort。在 settings.json 的 env 里加 CLAUDE_CODE_SUBAGENT_MODEL=sonnet，内置 Explore、Plan 就不会继承贵模型。
  • 项目没有 OpenSpec？ L3 方案写到 docs/plans/；或在项目里执行 openspec init --tools claude。
  • 知识库没生效？ 执行 dispatch-kb path，检查 ~/.claude/dispatch/config 里的 kb_dir。
  • 文档站没更新？ 执行 dispatch-pages list 看有没有这篇；退出码 4 表示已提交到本地但推送失败，在 ~/workbench/lhanman.github.io 里手动 git push。
  • 想下线一篇文档？ dispatch-pages remove <slug>。
  • 想拦截更多敏感词？ 在 ~/.claude/dispatch/config 的 pages_deny 里增加，逗号分隔。
  • 想脑暴？ 说「脑暴一下……」或执行 /dispatch:brainstorm；要落地就转入对应级别的流程，要留存就写笔记或发文档站。
  • 常驻开销多少？ 约 2.3k token/会话，用 claude plugin details dispatch 查看。
