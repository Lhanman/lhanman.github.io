方案评估 · 2026-09-19

小说 AI 改编评估

输入一个书名，产出三样东西：每章的高光原文与概述、章节漫画（可选）、旁白固定而每个角色音色不同的有声剧（可选）。本文回答四个问题：花多少钱、能不能做、怎么做、有什么风险。

结论

能不能做
三项功能技术上都能做。卡点在“书从哪来”，不在 AI 能力。只输入书名，模型背不出可靠的原文，所以书名只能当查找书源的钥匙。
边界
公版书、用户自己上传并且只自用，可以做；把受版权保护的小说做成漫画或有声剧对外发布，没有授权就不能做。
花多少钱
AI 调用费不贵。一部《西游记》量级的书，三项全做约 ¥600–1,900。真正的成本在开发和人工抽检。
可行① 高光 + 概述 可行，需抽检③ 多角色有声剧 能出图，质量不稳② 章节漫画

怎么算的

① 高光 + 概述：每章输入正文加约 3K token 的提示词、设定集和上一章概述，输出约 2K token（含低档思考）；另外全书先过一遍抽人物设定。书 A 合计输入约 250 万、输出约 30 万 token，Sonnet 5 批处理约 $4；书 B 输入约 1,100 万、输出约 250 万 token，约 $24。上限按 Opus 5 再加 10–20% 重试。
② 漫画：书 A 为 100 回 × 6 格 × 1.5 = 900 张 × ¥0.25 ≈ ¥225，加主要角色定妆图约 ¥50、分镜脚本的大模型费用约 ¥30–60。书 B 为 9,000 张 ≈ ¥2,250，加定妆 ¥100–200、分镜 ¥200–400。上限按 Seedream 5.0 pro 计。
③ 有声剧：书 A 为 80 万字 × ¥3/万字符 = ¥240，加台词归属的大模型费用 ¥30–70；若 8 个主角定制音色，再加 8 × ¥138 = ¥1,104。书 B 为 300 万字 ≈ ¥810–900，加大模型 ¥170–450；30 个定制音色再加 ¥4,140。
  • 音频时长：书 A 约 60 小时，书 B 约 220 小时。如果只演绎每章的高光片段（约 800 字/章），书 B 的 TTS 费用降到约 ¥240。
  • 成本波动最大的两项：定制音色的数量，和漫画的重试率。
  • 其他方案对比：Gemini 的 Nano Banana Pro 每张约 $0.13–0.24，是 Seedream 的 4–6 倍；MiniMax speech-2.8 HD 每百万字符约 $100，比豆包贵。
  • 开发人力（1 人）：① 约 1–2 周，③ 再加 2–3 周，② 再加 3–4 周。

02可行性

功能技术成熟度判断主要难点
① 高光 + 概述高可行书源；“原文”必须逐字准确，不能让模型编
③ 多角色配音中高可行，需人工抽检台词是谁说的（归属）判断不准，人物别名多，情绪表达
② 章节漫画中能出图，质量不稳跨章节角色长相一致、多人同框、内容审核拦截

额外提醒：Claude API 不对中国大陆开放。如果部署在国内，建议全部放在火山引擎：大模型用豆包 Seed 2.0，生图用 Seedream，配音用豆包语音。一个账号、一张发票，合规也更省事。

① 章节卡片 必做

  1. 段落编号
  2. 模型选段 + 写概述
  3. 程序切原文、校验

② 漫画 可选

  1. 分镜 JSON
  2. 定妆图（人工挑定）
  3. 逐格生图
  4. 程序渲染对白、拼页

③ 有声剧 可选

  1. 拆分旁白与台词
  2. 台词归属 + 情绪
  3. 音色映射、TTS
  4. ffmpeg 拼接，出字幕

关键设计点

设定集是核心

三个功能都通过人物 ID 引用同一份设定：名字、别名表、外貌描述、定妆图、音色 ID。这是跨章节保持一致的根本。做法是先对全书滚动抽取一遍人物，再合并去重。

高光原文防编造

  • 输入时给每个段落编号 [P12]。
  • 模型只返回段落编号和入选理由，由程序从原文切出段落。这样既保证逐字准确，输出 token 也少。
  • 概述和高光都用 JSON Schema 约束输出格式，走批处理接口。

漫画

  • 先由大模型写分镜 JSON：每格的场景、出场人物 ID、动作表情、镜头、对白。
  • 主要角色先各生成一张三视图定妆图，由人工挑定。
  • 逐格生图时，拼接固定画风前缀和人物外貌描述，并把定妆图作为多张参考图一起传入 Seedream。
  • 对白气泡由程序渲染，不让生图模型画中文字，最后程序拼页。

有声剧

  • 按引号（「」“”）拆分旁白和台词。
  • 大模型给每句台词标注说话人 ID 和情绪。
  • 旁白用固定音色。主角用音色设计或声音复刻（¥138/个）。配角按“性别 + 年龄段”从预置音色池里确定性分配，保证同一角色始终是同一个声音。
  • 用 ffmpeg 拼接并加停顿，输出 mp3 和字幕文件 SRT。

工程层面

  • 每一步的产出按“章节内容哈希 + 步骤 + 版本号”缓存，重跑不重复花钱。
  • 用任务队列支持断点续跑。
  • 做一个简单的人工抽检页面，重点抽检台词归属和漫画。

落地顺序

P01–2 周

用公版的《西游记》跑通 ①。

评估：引文准确率、概述质量

P12–3 周

做 ③，先做前 10 回。

放量标准：台词归属准确率达到 95% 以上

P23–4 周

做 ②，只给高光章节做。

这是最难的一项，放在最后

04风险

风险等级说明应对
版权最高从盗版站抓书违法。改编成漫画、有声剧，涉及改编权、表演权、信息网络传播权。逐章大量引用原文可能超出合理引用的范围只用公版书、已授权作品，或用户自传且仅自用；对外只放概述
合规高《人工智能生成合成内容标识办法》（2025-09-01 施行）要求给 AI 生成内容加标识；复刻真人声音需要本人授权；面向公众提供服务可能涉及算法或深度合成备案加显式和隐式标识；不复刻真人声音
内容审核高暴力、情色片段会被大模型、生图、TTS 拒绝，产出出现空缺预设降级：用文字卡或概述代替
质量高台词归属出错、人物长相漂移、别名识别不到、章节切分异常设定集 + 定妆参考图 + 人工抽检
成本失控中漫画反复重试，定制音色越加越多按书设预算上限，只给主角定制音色
供应商中价格调整、模型下线；豆包语音合成默认 10 并发调用层做抽象，可换供应商；按需购买并发
